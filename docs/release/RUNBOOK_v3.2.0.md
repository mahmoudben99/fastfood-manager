## ⚠️ #1 SECURITY PRIORITY (pre-existing, adoption-gated)
Your LIVE Supabase Phase-A policies still let the public anon key SELECT `owner_pins` (bcrypt hashes), `owner_orders`, and rewrite any `menu_sync`. This predates this release. It CANNOT be closed while v3.0.2/v1.6.5 clients are live because those tables are written via `upsert`, which PostgREST requires SELECT for. The fix path:
1. Ship v3.2.0 to both customers (below). v3.2.0 uses `owner_credentials` (not `owner_pins`) and device-authed writes.
2. Once BOTH La ZONE + HAVEN are confirmed on v3.2.0, apply `supabase/migrations/0003_rpcs.sql` (if not already) then `supabase/migrations/0004_phase_b_strict.sql` — the lockdown. Rollback: `supabase/rollback_0002.sql`.
Until then, treat the anon key as public and the exposure as known.

## Deployment sequence (staged, reversible)
1. **DONE by the run:** license server deployed + secrets set (`SIGNING_PRIVATE_KEY` MUST be base64 PKCS8 DER, not PEM — this bit us once), D1 migrated, cron live.
2. **Vercel env** (admin): set `LICENSE_ADMIN_BEARER` (= the worker's ADMIN_BEARER, in the run's secrets.env), `SERVER_CAPABILITY_SECRET` (≥32 random bytes), `SESSION_SECRET` (≥32), `ADMIN_PASSWORD`, `SUPABASE_SERVICE_ROLE_KEY`. Redeploy admin.
3. **Machine-id preflight:** on each customer PC run `npm run diagnostics:machine-id -- --json` — confirm the stored id is stable (old vs new derivation match). If mismatch, do an audited rebind, don't seed blind.
4. **Pre-bind D1** for the 2 customers BEFORE their machine_ids circulate (WP-C review #2 TOFU): admin-create their rows with the correct plan, and have their real desktop do the first `/trial/start` from a trusted network so it binds; or use `/v1/admin/mutate rebindDevice`. Machine ids: La ZONE `2CDD8ECC5AAF2DDD`, HAVEN `103461A52DE9D38A` (confirm plans first).
5. **Build + publish desktop:** `npm run package` → signed installer + `latest.yml`. Create the GitHub release (owner mahmoudben99/fastfood-manager) with BOTH the .exe and latest.yml (electron-updater needs latest.yml).
6. **Canary:** one friendly customer first — verify licensed, orders, printing, owner dashboard, updater. Then the rest.
7. **TV:** generate the release keystore (`keytool` cmd in `tv-app/README.md`), upload the 5 GH secrets, tag to trigger the signed build; field-test `adb install -r` v1→v2 (existing debug APKs need one uninstall/re-pair).
8. **Website:** publish `fastfood-website/` (static export in `out/`).
9. **Only after both customers on v3.2.0:** the RLS Phase-B lockdown (see #1).

- Desktop: previous GitHub release remains downloadable; electron-updater points at the repo. A bad v3.2.0 → publish the prior installer.
- License server: `wrangler rollback` to the prior version id; D1 migrations are additive.
- Admin: Vercel instant rollback to the prior deployment.
- Supabase: `supabase/rollback_0002.sql` restores the prior policy set.
- All work is on `megacode/integration`; `main` and `feature/ambient-tv-overhaul` are untouched.
